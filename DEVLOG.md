# Devlog

Здесь собрана история разработки Codex Account Switcher: что менялось, какие проблемы находились на реальных аккаунтах и что планируется дальше.

## 1 сентября 2026 — v2.2.1: refresh без ложного логаута

После первого релиза расширенной карточки выяснились две независимые проблемы.

### Невалидный refresh не означает мгновенный выход

OAuth мог вернуть `invalid_refresh_token`, пока access token продолжал работать ещё несколько дней. Приложение показывало «Авторизация истекла», хотя Codex по-прежнему получал лимиты и работал с аккаунтом.

Теперь состояния разделены:

- подтверждённо нерабочий refresh удаляется из локального профиля;
- рабочий access token остаётся нетронутым до своего настоящего `exp`;
- перед изменением создаётся резервная копия;
- профиль удаляется только после фактического истечения всей авторизации;
- бессмысленные повторные OAuth-запросы с мёртвым refresh больше не выполняются.

### Исправлены ответы HTTP 403 от OpenAI

Эндпоинты расширенной информации возвращали HTML-страницу Cloudflare вместо JSON. Access token при этом был исправен.

Клиент запросов приведён к ожидаемому OpenAI маршруту: добавлены `Origin`, `Referer`, совместимый User-Agent и HTTP/1.1. После исправления снова загружаются страна и валюта счёта, актуальный тариф и замаскированные способы оплаты.

Дополнительно одинаковые способы оплаты объединяются, поэтому одна карта больше не появляется в списке дважды.

### Проверка релиза

- production-сборка React/Vite;
- 8 Rust-тестов;
- `cargo clippy --all-targets -- -D warnings`;
- проверка форматирования и `git diff --check`;
- запуск собранного `.app` на реальном профиле;
- проверка подписи `.app` и контрольной суммы DMG;
- secret-scan исходников и скриншотов.

## 1 сентября 2026 — v2.2.0: подробная карточка и Refresh Broker

Главная задача версии — превратить простой переключатель файлов в менеджер состояния аккаунтов.

Добавлено:

- срок жизни access token и дата последнего refresh;
- тариф, дата окончания подписки и лимиты Codex;
- страна счёта, валюта и безопасно замаскированные способы оплаты;
- ручное продление токенов с атомарной записью и backup;
- локальный Refresh Broker на `127.0.0.1:1456`;
- перехват ротации токенов, выполненной Codex CLI;
- автоматическое удаление только подтверждённо истёкших профилей;
- подробное окно аккаунта без немедленного переключения по случайному клику.

Broker сериализует OAuth-ротации глобальной блокировкой. Пока access token действителен, Codex получает текущую пару без лишнего обмена. После истечения запрос передаётся OAuth-серверу, а свежая пара сохраняется в активный профиль.

## 1 сентября 2026 — интеграция KeyCrop

Первоначальная синхронизация не находила аккаунты, потому что данные авторизации находились глубже в JSON покупки и иногда были дополнительно сериализованы строкой.

Импорт был расширен:

- поддержана постраничная загрузка `/api/account/purchases`;
- добавлен рекурсивный поиск вложенного `auth.json`;
- распознаются обычный Cookie header и экспорт EditThisCookie/Cookie-Editor;
- HTML entities из сообщений и вставок нормализуются;
- дубликаты определяются по идентификатору Codex-аккаунта;
- каждый новый refresh token сразу проверяется однократной ротацией;
- уже использованные и нерабочие токены отклоняются до добавления профиля.

Cookie KeyCrop хранится только в системном хранилище секретов и не передаётся в React-интерфейс.

## Первый этап — перенос на Tauri 2

Исходный macOS-переключатель был переписан на React, TypeScript, Rust и Tauri 2. Интерфейс получил визуальный язык KeyCrop, а работа с файлами, сетью и секретами была вынесена в Rust-бэкенд.

Базовая версия уже умела:

- хранить несколько локальных профилей;
- определять активный аккаунт;
- проверять лимиты через изолированный `CODEX_HOME`;
- переключать `~/.codex/auth.json`;
- создавать backup перед заменой;
- работать без отправки токенов во frontend.

## Как устроено приложение сейчас

```text
KeyCrop API ──► Rust importer ──► защищённые локальные профили
                                      │
Codex app-server ◄── изолированный CODEX_HOME
                                      │
                                      ▼
                              React-интерфейс
                         только безопасные DTO

Codex OAuth ◄──► Refresh Broker ◄──► активный auth.json
```

Cookies, access token, refresh token и полные ответы с реквизитами не включаются в frontend DTO и не выводятся в журнал.
